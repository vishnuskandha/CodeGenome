## 🧬 Core Architecture — `codegenome.py`

### Design Philosophy
Everything lives in **one file** with **7 logically separated class modules**. Each class acts as an independent engine in a sequential pipeline.

```
User Input
    ↓
┌─────────────────────────┐
│   GitHubFetcher         │ ← Streams files via API (no clone)
├─────────────────────────┤
│   CodeParser            │ ← AST + regex extraction
├─────────────────────────┤
│   DependencyGraphBuilder│ ← NetworkX dependency graph
├─────────────────────────┤
│   SecurityScanner       │ ← Vulnerability detection + fix suggestions
├─────────────────────────┤
│   RiskEngine            │ ← Quantified risk score (0–100)
├─────────────────────────┤
│   LLMReasoner           │ ← OpenRouter AI (compressed context)
├─────────────────────────┤
│   ChatInterface         │ ← Rich CLI with tables & colors
└─────────────────────────┘
    ↓
Formatted Output + Interactive Chat
```

## 📦 Module Breakdown

### Module 1 — `GitHubFetcher` (Lines 85–205)
**Purpose:** Stream repository files via GitHub API without cloning.

| Method | What It Does |
|--------|-------------|
| `__init__(repo_url, token)` | Parses owner/repo from URL, sets auth headers |
| `get_repo_tree(max_files)` | Fetches recursive file tree (tries `main` → `master`) |
| `get_file_content(path)` | Downloads single file content via base64 decoding |
| `fetch_code_files(max_files)` | Filters & fetches all supported file types |

**Supported Languages (30+):**
```
Python  JavaScript  TypeScript  Java  C  C++  Go  Rust  Ruby
PHP  C#  Swift  Kotlin  Scala  Arduino(.ino)  HTML  CSS
JSON  YAML  XML  Markdown  and more...
```

**Key Design Decision:** READMEs are fetched separately and used for architecture detection.

---

### Module 2 — `CodeParser` (Lines 212–317)
**Purpose:** Extract semantic metadata from source files.

**For Python files** → Full AST parsing:
- Imports (`import x`, `from x import y`)
- Class definitions
- Function definitions
- Cyclomatic complexity (branch counting)
- Entry point detection (`if __name__ == "__main__"`)

**For all other languages** → Regex-based parsing:
```python
# Import patterns
r'#include <file.h>'     # C/C++
r'require("module")'     # JavaScript
r'use crate::module'     # Rust

# Function patterns
r'void functionName('    # C/Java
r'func main('            # Go
r'fn process('           # Rust

# Class patterns
r'class ClassName'       # Python/Java/C++
r'struct DataType'       # C/Rust
r'interface IHandler'    # Java/TypeScript
```

---

### Module 3 — `DependencyGraphBuilder` (Lines 324–368)
**Purpose:** Build directed dependency graph using NetworkX.

| Method | What It Does |
|--------|-------------|
| `build_graph(metadata)` | Creates nodes (files) and edges (imports) |
| `detect_circular_dependencies(graph)` | Finds cycles using `nx.simple_cycles()` |
| `calculate_coupling(graph)` | Measures graph density → low / medium / high |

**Coupling Levels:**
| Density | Level |
|---------|-------|
| < 0.1 | Low |
| 0.1 – 0.3 | Medium |
| > 0.3 | High |

---

### Module 4 — `SecurityScanner` (Lines 375–479)
**Purpose:** Detect vulnerabilities with **fix suggestions** and **code context**.

#### Vulnerability Patterns

| Severity | Pattern | Example | Fix |
|----------|---------|---------|-----|
| **CRITICAL** | Hardcoded secrets | `token = "abc123"` | Use `os.getenv()` |
| **CRITICAL** | AWS/GitHub credentials | `AWS_SECRET = "..."` | Use secrets manager |
| **HIGH** | `eval()` usage | `eval(user_input)` | Use `ast.literal_eval()` |
| **HIGH** | `exec()` usage | `exec(code)` | Refactor logic |
| **HIGH** | `shell=True` | `subprocess.run(cmd, shell=True)` | Use `shell=False` + list |
| **MEDIUM** | Weak hashing | `hashlib.md5()` | Use `sha256()` / `bcrypt` |
| **MEDIUM** | Open CORS | `Origin: *` | Restrict domains |
| **MEDIUM** | Debug mode | `debug=True` | Use env variable |
| **LOW** | Large functions | `>200 lines` | Split into smaller funcs |

#### Enhanced Reporting
Each issue includes:
- 📁 **File** and **📍 Line number** — exact location
- **Code context** — 2 lines before & after the issue
- ✅ **Fix suggestion** — actionable remediation

```
Issue #1: CRITICAL
📁 File: config.py
📍 Line: 45
⚠️  Problem: Hardcoded secret detected

Context (before):
  import os
  # Configuration

→ Line 45: API_KEY = "sk-1234567890abcdef"

Context (after):
  DATABASE_URL = "postgres://..."
  DEBUG = True

✅ Fix: Move to environment variable: os.getenv('API_KEY')
```

### Module 5 — `RiskEngine` (Lines 486–531)
**Purpose:** Calculate a normalized risk score from 0 to 100.

**Formula:**
```
risk = (critical × 5) + (high × 3) + (medium × 2) + (low × 1)
     + (avg_complexity / 10)
     + (circular_dependencies × 2)

normalized = min(100, risk × 2)
```

| Score | Level | Color |
|-------|-------|-------|
| 0–39 | LOW | 🟢 Green |
| 40–69 | MEDIUM | 🟡 Yellow |
| 70–100 | HIGH | 🔴 Red |

---

### Module 6 — `LLMReasoner` (Lines 538–623)
**Purpose:** AI-powered codebase Q&A via OpenRouter.

**How It Works:**
1. **Context compression** — repo data → structured summary:
   - Architecture type + pattern
   - Entry points + coupling level
   - Top 20 dependencies
   - Security issues by severity
   - First 10 files with classes/functions
2. **Send to LLM** — compressed context + user question
3. **Receive answer** — concise, technical response

**Configuration:**
```python
model = "anthropic/claude-3.5-sonnet"  # Default
max_tokens = 500                        # Concise answers
base_url = "https://openrouter.ai/api/v1"
```

> [!TIP]
> Change the model by editing line 541 in `codegenome.py`.  
> Options: `google/gemini-2.0-flash-exp`, `openai/gpt-4o`, `meta-llama/llama-3-70b`

---

### Module 7 — `ChatInterface` (Lines 630–734)
**Purpose:** Rich terminal UI with tables, colors, and interactive chat.

**Display Components:**
- Architecture summary table (type, pattern, coupling, files, lines)
- Security analysis table (risk score + issue counts by severity)
- Detailed security report (top 5 issues with context + fixes)
- Interactive chat loop

**Chat Commands:**
| Input | Action |
|-------|--------|
| Any question | Sends to LLM with repo context |
| `exit` / `quit` / `q` | Exits the program |
| `Ctrl+C` | Force exit |

## 🎓 Academic / Viva Reference

### Why Single File?
> Demonstrates architectural abstraction within minimal implementation surface. Seven logically isolated class modules simulate a microservice pipeline inside a monolith.

### Key Concepts Demonstrated
| Concept | Where |
|---------|-------|
| AST Parsing | `CodeParser` — Python `ast` module |
| Graph Theory | `DependencyGraphBuilder` — NetworkX cycle detection |
| Static Analysis | `SecurityScanner` — regex + AST vulnerability scanning |
| Risk Quantification | `RiskEngine` — weighted scoring + normalization |
| Context Compression | `LLMReasoner` — 10:1 compression ratio |
| Token Optimization | Structured summaries instead of raw code dumps |

### Complexity Analysis
| Operation | Time Complexity |
|-----------|----------------|
| File fetch | O(n) — n = files |
| AST parse | O(n × m) — m = nodes per file |
| Graph build | O(V + E) |
| Cycle detection | O(V + E) |
| Security scan | O(n × p × l) — p = patterns, l = lines |
| Risk calculation | O(k) — k = issues |

## 🔧 Troubleshooting

| Problem | Solution |
|---------|----------|
| `OPENROUTER_API_KEY not found` | Check `.env` file exists and has valid key |
| `Failed to fetch repo tree: 403` | GitHub rate limit — set `GITHUB_TOKEN` in `.env` |
| `Failed to fetch repo tree: 404` | Check repo URL is correct and public |
| `No code files found` | Repo may have unsupported file types |
| LLM returns generic answers | Try a different model (edit line 541) |
